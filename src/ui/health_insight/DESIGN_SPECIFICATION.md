# Health Insight Design Specification（Phase 6 TASK1.114-A）

## 目的

把使用者提供的五張「拙趣風格」Health Insight視覺參考圖，轉換成
正式的UI/UX設計規格——本次任務**只做分析跟規格文件**，**不**
實作任何UI程式碼、**不**修改任何既有原始碼、**不**產生任何
新圖片。這份文件是`Visual Reference Images → Design
Specification → Future UI Component Implementation`這條流程
的中間產物，供未來實作任務（TASK1.114-B或之後）直接依據落地。

## 分析素材

使用者附上的五張圖：

1. **角色設定圖（Character Sheet）**：「Health Insight
   Companion」——豆芽/種子造型吉祥物三種姿勢（抱心/喝茶/揮手
   歡呼），加上五個小圖示（發芽/杯子/愛心/筆記本/太陽）跟五色
   色票。
2. **Dashboard手機畫面**：「今日健康洞察」，四張卡片（今天的
   摘要/健康觀察/今日建議/進度追蹤）+ 底部四個分頁的Tab Bar。
3. **Input Experience手機畫面**：「今天想聊什麼？」，三張引導
   式問題卡（睡眠/精神/運動），每張搭配角色插畫跟三選項或二
   選項的圓角選項按鈕，底部一個大型CTA按鈕。
4. **「健康觀察」主題卡**：角色拿放大鏡看發芽幼苗的插畫。
5. **「今日建議」主題卡**：角色開心喝茶、周圍有枕頭/毯子/鞋子
   的插畫。

## 1. Visual Identity（整體視覺識別）

### Overall Emotional Feeling（整體情緒感受）

溫暖、鬆軟、像看到一個小夥伴窩在旁邊——五張圖沒有一張出現
"數據感"或"精密感"，全部都是生活化的日常情境（喝茶、休息、
散步、看幼苗發芽）。整體情緒是**放鬆**而不是**警覺**，這正是
規格要求的"陪你慢慢理解自己"而不是"監控使用者健康數據"的
具體視覺體現。

### Brand Personality（品牌個性）

角色個性是"溫柔、耐心、不催促"——插畫裡角色的表情永遠是
瞇眼微笑或閉眼放鬆，沒有一張是誇張的驚訝/緊張表情。角色背著
一個有小芽圖案的側背包，給人一種"陪你一起去探索"的旅伴感，
而不是"站在你對面診斷你"的權威感。

### User Impression（使用者印象）

使用者第一眼會覺得這是一個"生活陪伴類"應用（跟記帳/日記/
種植遊戲app的調性接近），而不是"醫療/健康追蹤類"應用——這個
印象差異對TASK1.106已確認的產品定位（不是傳統健康追蹤app）
至關重要。

### Illustration Personality（插畫角色個性）

主角是一個**芽苗系**生物角色：米色圓潤身體、頭頂一株雙葉嫩芽、
圓潤紅暈臉頰、簡單的黑點眼睛（開心時瞇成弧線）、穿著赤陶橘色
的針織風上衣、背赤陶橘色小背包（背包上有嫩芽小圖案）。這個
角色貫穿所有畫面，是整個視覺系統的"代言人"，情緒表達單純
（開心/放鬆/專注/期待四種基本情緒足夠涵蓋所有情境）。

### Relationship Between User and Product（使用者跟產品的關係）

視覺語言傳達的關係是"角色陪使用者一起看、一起發現"——例如
"健康觀察"主題圖是角色自己拿著放大鏡看幼苗（不是看使用者的
數據），"今日建議"主題圖是角色自己示範"早點休息、喝溫水"這個
建議（角色以身作則，不是命令使用者）。這是**同伴視角**，不是
**監控者視角**。

## 2. Color System（顏色系統）

### 色彩來源

角色設定圖底部提供五個色票（米杏、赤陶橘、蜂蜜黃、鼠尾草綠、
深棕），Dashboard/Input畫面的實際使用進一步確認了每個顏色
對應的語意角色。

### Primary Colors（主色）

| 顏色 | 建議HEX | 用途 |
|---|---|---|
| 赤陶橘（Terracotta） | `#C1694A` | 角色上衣/背包、CTA按鈕、Recommendation/Care相關強調、愛心圖示 |
| 赤陶橘深 | `#96502F` | 按鈕按下狀態、深色描邊線稿、強調文字 |

### Secondary Colors（輔色）

| 顏色 | 建議HEX | 用途 |
|---|---|---|
| 蜂蜜黃（Honey） | `#E3A73E` | 太陽圖示、茶杯、Progress/正向強調 |
| 鼠尾草綠（Sage) | `#8A9B5E` | 嫩芽葉片、Observation區塊強調、Growth相關圖示 |
| 鼠尾草綠深 | `#5F6F3E` | 綠色系文字/深色葉脈細節 |

**跟既有`design_tokens.js`的差異**：目前既有token（TASK1.114）
**沒有**鼠尾草綠這個色相，只有赤陶橘系+蜂蜜黃系兩組。參考圖
明確顯示鼠尾草綠是Observation卡片跟嫩芽圖示的**專屬**語意色
（跟Recommendation的赤陶橘、Progress的蜂蜜黃形成三卡片各自
一個強調色的節奏），這是後續實作需要新增的色彩token。

### Background Colors（背景色）

| 顏色 | 建議HEX | 用途 |
|---|---|---|
| 頁面底色 | `#F6ECDD` | 整體頁面背景，米杏色，帶溫暖紙質感 |
| 卡片底色 | `#FFFCF5` | 卡片背景，比頁面底色更亮一階，製造輕微層次 |

### Card Colors（卡片色）

Dashboard卡片：白/米白底 + 柔和陰影，無明顯邊框。
Input問題卡：白/米白底 + **可見的暖棕色細邊框**（而不是陰影
為主）——這是兩種畫面刻意使用的**不同卡片處理方式**，見下方
第4節詳述。

### Button Colors（按鈕色）

| 顏色 | 建議HEX | 用途 |
|---|---|---|
| CTA主按鈕底色 | `#C1694A` | 大型主要行動按鈕（例如"開始整理我的健康洞察"） |
| CTA按鈕文字 | `#FFFBF2` | 按鈕上的文字，暖白色不是純白 |
| 選項按鈕－正向 | `#E3E4B0` | 三選項裡"很好/有精神"這類正向選項的底色，淡黃綠 |
| 選項按鈕－中性 | `#EBE0C8` | "普通/還可以"這類中性選項的底色，淡卡其色 |
| 選項按鈕－待改善 | `#DCAFA0` | "不太好/有點累"這類選項的底色，柔霧玫瑰色（**刻意不用紅色**） |
| 選項按鈕－肯定(是/有) | `#C7D19E` | 二選一裡"有"這類肯定選項的底色，淡草綠 |

### Accent Colors（強調色）

心形圖示：赤陶橘系（`#C1694A`跟更亮的珊瑚色`#D98872`交替
使用於裝飾性愛心）。太陽笑臉圖示：蜂蜜黃`#E3A73E`。手繪裝飾
短線（角色周圍的動態小短線）：赤陶橘/蜂蜜黃交替使用，純裝飾
用途，不承載語意。

### Usage Rules（使用規則）

- 每張卡片的圖示+標題底線只使用**一個**強調色（赤陶橘/鼠尾草
  綠/蜂蜜黃三選一），不要在同一張卡片內混用多個強調色造成
  視覺雜亂。
- 三選項評分類的選項按鈕**必須**使用語意色階（正向/中性/
  待改善），不能三個選項都用同一個顏色，否則使用者無法直覺
  分辨選項的傾向。
- 背景色永遠是米杏色系的深淺變化，卡片永遠比背景亮一階，
  維持"紙上貼一張卡片"的層次感。

### Forbidden Colors（禁止色）

- ❌ 醫療藍（`#0066CC`、`#007BFF`這類冷色系飽和藍）——整套
  參考圖完全沒有出現任何藍色系顏色用在UI結構上（月亮/夜晚
  窗景的深藍色是**插畫場景色**，不是UI結構色，不算例外）。
- ❌ 高飽和度警示紅（`#FF0000`、`#DC3545`這類刺眼紅）——"待
  改善"這類選項用的是柔霧玫瑰色`#DCAFA0`，不是紅色。
- ❌ 純白`#FFFFFF`當主要背景——所有背景都帶有米杏色調。
- ❌ 純黑`#000000`當主要文字色——文字色應該是深棕色系。
- ❌ 任何高飽和度的螢光色/漸層炫彩色——整套色彩都是低飽和度
  的大地色系。

## 3. Typography（字體方向）

### Title Style（標題樣式）

參考圖的主標題（"今日健康洞察"、"今天想聊什麼？"、"健康觀察"、
"今日建議"）使用的是**手寫/麥克筆風格字體**，筆畫粗、帶手感
弧度，顏色是深棕色，搭配一條手繪的顏色底線（赤陶橘/鼠尾草綠/
蜂蜜黃，對應卡片主色）。中文字重建議使用系統粗黑體
模擬（純CSS無法完美重現手寫字體筆觸，未來若要更貼近參考圖，
需要另外引入一款手寫感中文字型，這是本次任務明確標註的"未來
資產需求"之一，見下方第7節）。

### Subtitle Style（副標題樣式）

主標題底下的說明文字（例如"陪你慢慢理解自己"、"用幾個小問題，
整理今天的身體感受"）使用**一般字重**的中等大小文字，顏色比
主標題淺一階（暖棕灰），是安靜的輔助說明，不搶主標題的視覺
重量。

### Body Text Style（內文樣式）

卡片內的敘述文字（例如"今天的你，整體狀態穩穩的"）使用清晰的
無襯線字體，深棕色，行高寬鬆（延續低壓力閱讀節奏，不是密集
排版）。

### Button Text Style（按鈕文字樣式）

CTA按鈕文字用中等偏粗字重、暖白色，字級比內文稍大，確保在
赤陶橘底色上有足夠對比度但不刺眼。選項按鈕文字用一般字重，
深棕色，搭配左側一個小emoji/圖示。

### Emphasis Style（強調樣式）

參考圖沒有使用粗體/顏色強調單一詞語的做法，而是用**整張卡片
的標題+底線+圖示組合**來建立視覺層級，內文本身維持一致字重，
不在句子中間做局部強調——這跟"低壓力、不用視覺噪音抓住使用者
注意力"的設計原則一致。

### Font Size Hierarchy（字級層級）

主標題 > 卡片標題 > 副標題/內文 > 按鈕文字 ≈ 選項文字 >
說明性小字（例如百分比/次要標籤）。跟既有`design_tokens.js`
的`TYPOGRAPHY_TOKENS`層級（heading 22px → subheading 16px →
body 15px → cardText 14px → caption 12px）方向一致，不需要
調整既有數值，只需要在heading層級**額外**定義一個"手寫感"
的視覺處理（底線裝飾），這是新增而非取代既有token。

### Readability Rules（可讀性規則）

- 深棕色文字在米杏/白底卡片上的對比度已經足夠（延續WCAG
  基本可讀性要求，深棕`#5B3A29`在`#FFFCF5`底色上對比度充足）。
- 行高刻意寬鬆（1.6~1.8倍），呼應"慢慢看"、"不急"的產品調性。
- 每張卡片只放一段簡短敘述，不會出現大段落文字。

## 4. Component Visual Language（元件視覺語言）

### Cards（卡片）

#### 共同規則

- **Border radius**：大圓角，約20~24px（比既有token的20px
  略大或相同，方向一致，不需要調整）。
- **Shadow**：Dashboard卡片使用柔和、暖色調的陰影（例如
  `0 6px 20px rgba(150, 80, 47, 0.12)`），陰影顏色帶一點
  赤陶色調，而不是純黑陰影——這點既有`CARD_STYLE_TOKENS.
  boxShadow`已經正確做到（`rgba(168, 95, 53, 0.12)`）。
- **Padding**：卡片內邊距寬鬆，圖示/標題/底線在頂部一列，
  內文在下方，插畫（如果有）靠右或靠左對齊，不會佔滿整個
  卡片寬度。
- **Illustration position**：Dashboard卡片的角色插畫固定放在
  卡片**右側**；Input問題卡的角色插畫固定放在卡片**左側**，
  文字內容放右側——這是兩種畫面刻意採用**鏡像**排版的細節，
  未來實作時要注意區分。

#### HealthSummaryCard（今天的摘要）

- 圖示：嫩芽（🌱），底線色：赤陶橘。
- 內容：一句話狀態總結（"今天的你，整體狀態穩穩的"）。
- 插畫：太陽+雲朵的小場景插畫，放在卡片右側，傳達"今天天氣
  很好/心情平穩"的隱喻，不是放角色本人。
- 現況對照：既有`health_summary_card.js`已經是"圖示+標籤+
  一句話說明"的結構，跟參考圖的資訊密度一致，未來只需要換上
  對應插畫、加上底線裝飾即可，結構不需要大改。

#### ObservationCard（健康觀察）

- 圖示：嫩芽（🌱），底線色：**鼠尾草綠**（不是既有的赤陶橘/
  蜂蜜黃，這是新增的專屬色）。
- 內容：描述一個注意到的模式（"這幾天作息比較不固定，身體
  像是在提醒你慢一點"）——語氣是**觀察轉述**，不是**警告**。
- 插畫：角色側躺休息的插畫，搭配深夜窗景（月亮+星星）跟
  一顆石頭+盆栽，放在卡片右側，情境化地呈現"作息不規律"這個
  觀察，不使用任何圖表/數字視覺化。
- 現況對照：既有`observation_card.js`目前是逐筆列出`{type,
  value}`（例如"活動記錄：3"），跟參考圖"一段完整敘述句"的
  呈現方式有落差——這是**未來需要新增的呈現層轉換**：把多筆
  結構化observation彙整成一句話敘述，而不是每筆單獨列成一張
  小卡片。本次任務只記錄這個落差，不在這裡實作轉換邏輯。

#### RecommendationCard（今日建議）

- 圖示：愛心（❤️），底線色：赤陶橘。
- 內容：具體、可執行的單一建議（"今晚提早30分鐘休息，喝一杯
  溫水"）——語氣是**溫柔提議**，不是**指令**。
- 插畫：角色開心喝茶的插畫，放在卡片右側，傳達"照顧自己"的
  情境。
- 現況對照：跟ObservationCard一樣，既有`recommendation_
  card.js`目前逐筆列出`{type, value}`，未來需要彙整成單一句
  建議文字的呈現層轉換。

#### ProgressPlaceholder（進度追蹤）

- 圖示：長條圖（📊代表，但參考圖用的是手繪柱狀小圖示），底線
  色：蜂蜜黃。
- 內容：誠實的"資料還不夠"訊息（"累積更多資料後，這裡會看見
  你的變化"）——這跟既有`progress_card.js`的"這個功能還在
  準備中"文案精神**完全一致**，是本次分析裡跟既有實作**吻合
  度最高**的一個元件。
- 插畫：一條由小幼苗排列成的虛線成長路徑，帶一個愛心終點，
  隱喻"雖然現在還沒有資料，但持續記錄會慢慢長出成果"。
- 現況對照：既有`progress_card.js`結構已經正確，只需要替換
  emoji佔位符成對應插畫，底線色需要從目前沒有底線裝飾的樣式
  新增蜂蜜黃底線。

#### BehaviorPatternPlaceholder（行為模式，參考圖沒有直接對應畫面）

五張參考圖沒有出現"行為模式"這個獨立卡片的具體畫面，但延續
"健康觀察"主題卡（圖4，角色拿放大鏡看幼苗）傳達的"耐心觀察"
意象，建議BehaviorPatternPlaceholder沿用**放大鏡+幼苗**這組
插畫語彙（跟ObservationCard的深夜休息插畫做出區隔），底線色
建議沿用鼠尾草綠（跟Observation同一個語意色系，因為Behavior
Pattern在TASK1.108定義上也是Observation的進階延伸）。

#### QuestionCard（引導式問題卡）

- **卡片處理方式不同於Dashboard卡片**：Input畫面的問題卡是
  **白底+暖棕色細邊框**（約1.5~2px），陰影很淺或幾乎沒有，
  跟Dashboard卡片"白底+明顯陰影、無邊框"的處理方式相反——
  這是本次分析發現的一個**具體、需要落地的視覺規則差異**。
- 排版：角色插畫在**左側**（跟Dashboard的"插畫在右側"相反），
  問題文字在插畫右側或下方，選項按鈕排成一列在最下方。
- 選項按鈕：圓角膠囊形（pill shape），左側搭配一個小emoji
  圖示，背景色依照語意分成三階（正向/中性/待改善）或二階
  （肯定/否定）——見上方第2節Button Colors。
- 現況對照：既有`question_card.js`的`createChoiceQuestionCard()`
  目前所有選項按鈕使用同一種樣式（沒有語意色階），
  `createInputQuestionCard()`的卡片樣式沿用共用的`.hi-card`
  （陰影樣式，沒有邊框樣式）。未來實作需要：(1) 新增一個
  邊框樣式的卡片變體給問題卡專用；(2) 讓選項按鈕接受一個
  語意分類參數（positive/neutral/negative或yes/no），對應
  不同底色。

#### ErrorCard（參考圖沒有直接對應畫面）

五張參考圖沒有錯誤狀態的範例，但延續整體"溫柔、不指責"的
視覺語言，建議ErrorCard：
- 使用跟"待改善"選項相同的柔霧玫瑰色`#DCAFA0`當強調色（**不是
  警示紅**），避免跟其他三張正向卡片（赤陶橘/鼠尾草綠/蜂蜜黃）
  的強調色混淆，同時维持溫暖色系家族的一致性。
- 插畫建議使用角色**輕輕闔眼、稍微歪頭**的表情（表達"這裡
  暫時卡住了，但沒關係"），而不是驚訝/慌張的表情。
- 現況對照：既有`error_card.js`目前使用🍂（落葉）當emoji
  佔位符，色彩上`COLOR_TOKENS.caution`（`#B8703F`，赭石色）
  方向正確但比參考圖的柔霧玫瑰色更偏橘紅，建議未來調整成
  更接近`#DCAFA0`的柔和玫瑰色調，讓Error狀態跟"待改善"選項
  的色彩語言統一。

### Buttons（按鈕）

#### Primary Button（主按鈕，例如CTA"開始整理我的健康洞察"）

- 形狀：完全圓角的膠囊形（border-radius約等於高度的一半）。
- 顏色：赤陶橘底`#C1694A` + 暖白字`#FFFBF2`。
- 尺寸：滿版寬度（扣除頁面左右邊距），高度足夠大（約52~56px），
  符合行動裝置觸控友善的最小尺寸。
- 裝飾：按鈕周圍點綴手繪短線（動態感），純裝飾，不影響點擊
  區域。

#### Secondary Button（次要按鈕，參考圖沒有明確範例）

建議：赤陶橘**外框**+赤陶橘文字+透明/米白底，跟Primary Button
形成"實心=主要行動、外框=次要行動"的對比慣例，圓角/尺寸規則
沿用Primary Button。

#### Selection Button（選項按鈕，即Input畫面的選項chip）

- 形狀：圓角膠囊形，比Primary Button小、寬度依內容自適應
  （不是滿版）。
- 顏色：依語意分類使用第2節定義的色階（正向/中性/待改善或
  肯定/否定）。
- 內容：左側小emoji圖示 + 文字，置中排列。
- 選中狀態（參考圖沒有明確畫出"已選中"視覺，建議）：選中時
  邊框加粗或底色加深一階，並可加上一個小勾勾圖示。

#### Disabled Button（停用狀態，參考圖沒有範例）

建議：底色降低飽和度、文字顏色變淺（例如`COLOR_TOKENS.
textSecondary`降低opacity至0.5），維持相同形狀，不使用灰階
（維持整體暖色調一致性，不要因為disabled狀態突然跳出冷灰色）。

#### Hover / Active State（互動狀態，參考圖是靜態圖，無法直接
觀察，建議延續整體"低壓力"原則）

- Active（按下）：輕微縮小（scale 0.97）+ 底色加深一階，不使用
  瞬間變色/閃爍效果。
- Hover（桌面滑鼠情境）：輕微上浮（陰影加深一點），行動裝置
  觸控情境不需要hover狀態。

### Input Components（輸入元件）

- **Question Card**：見上方Cards章節QuestionCard小節。
- **Option Chips**：見上方Buttons章節Selection Button小節。
- **Selection Style**：單選（例如睡眠品質三選一）用互斥選中
  狀態；如果未來有"複選"情境（參考圖沒有出現），建議用同樣的
  chip樣式但允許多個同時選中。
- **Confirmation Interaction**：Input畫面底部的大型CTA按鈕
  （"開始整理我的健康洞察 →"）扮演"確認送出"的角色，按鈕文字
  帶一個箭頭符號暗示"前進到下一步"，這個模式建議保留給所有
  Input Experience流程的最後一步使用。

## 5. Illustration System（插畫系統）

### Character Style（角色風格）

芽苗系吉祥物：圓潤米色身體（近似橢圓形/水滴形，底部略寬）、
頭頂一株對生雙葉嫩芽（鼠尾草綠）、圓形紅暈臉頰（珊瑚粉）、
簡單黑點眼睛（睜眼時）或弧形閉眼線條（放鬆/微笑時）、簡單
弧線嘴巴、短胖四肢、穿赤陶橘色針織感上衣、背赤陶橘色側背包
（背包正面有一個小嫩芽圖案裝飾）。

### Drawing Style（繪製風格）

**色鉛筆/蠟筆質感**——所有插畫線條跟填色都帶有明顯的顆粒/
筆觸紋理，不是平滑的向量填色，也不是漸層感。輪廓線是深棕色，
線條粗細不均勻（手繪感），填色會略微超出/未完全對齊輪廓線
（刻意的"拙"感，這正是「拙趣」風格名稱的視覺體現）。

### Line Style（線條風格）

輪廓線：深棕色、中等粗細、不完全閉合/略帶抖動的手繪線條。
裝飾性短線（角色周圍表示活力/驚喜的小短線）：短促、方向
放射狀分佈、赤陶橘/蜂蜜黃交替。

### Texture（紋理）

整體插畫（含背景紙張）帶有類似色鉛筆/粉彩紙的顆粒紋理，不是
乾淨平滑的數位插畫質感——這個紋理感是「拙趣」風格最核心的
辨識特徵之一，純CSS技術很難完美重現（CSS濾鏡/SVG
noise可以近似模擬紙張紋理，但角色插畫本身的手繪筆觸質感
需要真正的插畫資產，不是CSS能生成的）。

### Expression（表情）

觀察到四種基本表情，建議定義成未來的表情資產需求：
1. **平靜/滿足**（閉眼弧線笑容）——用於Summary/一般狀態
2. **放鬆/休息**（半閉眼，搭配道具如茶杯/枕頭）——用於
   Recommendation/自我照顧情境
3. **開心/歡呼**（睜眼大笑，張開雙手/揮手）——用於正向回饋/
   鼓勵情境
4. **專注/好奇**（睜眼，搭配放大鏡等道具）——用於Observation/
   探索情境

建議未來新增第五種表情：
5. **溫和的抱歉/暫停**（微歪頭，輕輕闔眼但嘴角依然放鬆）——
   用於ErrorCard情境，參考圖沒有直接範例，是本次分析新增的
   需求。

### Placement Rules（放置規則）

- 角色在Dashboard標題區塊固定放在**右上角**，跟標題文字水平
  對齊。
- 角色在卡片內固定靠**一側**（Dashboard卡片靠右、Input問題卡
  靠左），不會置中或跨越文字區域。
- 角色永遠搭配一個**情境道具**（茶杯、放大鏡、枕頭+毯子、
  背包）強化該卡片的語意，不會讓角色"空手"出現在功能性卡片裡
  （空手的角色只出現在角色設定圖/品牌識別情境）。
- 裝飾性元素（愛心、短線、嫩芽）可以自由散布在插畫周圍當
  氛圍點綴，但不會蓋住文字或角色臉部。

確認每個插槽未來需要的**具體插畫內容**（目前都是emoji佔位符，

## 6. Background System（背景系統）

### Page Background（頁面背景）

米杏色`#F6ECDD`，帶輕微紙張顆粒紋理（可用CSS
`background-image`疊加細緻noise紋理模擬，或簡化為純色，
細節留給實作任務決定）。

### Section Background（區塊背景）

Dashboard標題區塊（含角色插畫）背景延續頁面底色，不額外加卡片
框，讓角色像是"站在紙面上"而不是"被裝在盒子裡"。

### Card Background（卡片背景）

白/米白`#FFFCF5`，比頁面背景亮一階，搭配柔和陰影（Dashboard
卡片）或暖棕細邊框（Input問題卡）製造區隔——見第4節詳細
規則。卡片內部如果有情境插畫，插畫本身可能帶一個更深的局部
背景色塊（例如深夜窗景是深藍色矩形、草地場景是綠色橢圓），
這些是插畫資產內部的細節，不是卡片本身的背景色。

### Empty State Background（空狀態背景）

延續Card Background規則，不需要額外的"空狀態專屬"背景色——
參考圖的ProgressPlaceholder（"累積更多資料後..."）就是用
一般卡片背景+誠實文案+象徵性插畫（成長路徑）處理空狀態，
不是用特殊的灰階/虛線框"未完成"視覺處理。這個原則也應該
套用到既有`observation_card.js`/`recommendation_card.js`的
`hi-empty-state`樣式：空狀態不代表"故障"或"缺失"，應該跟
正常卡片視覺一致，只是內容換成鼓勵性文字。

## 8. Responsive Design Direction（響應式設計方向）

### Dashboard Structure（Dashboard結構）

單欄垂直卡片堆疊，卡片之間留白充足（不是緊密網格），這是
典型的行動裝置優先版面。

### Card Arrangement（卡片排列）

固定順序：標題區塊（含角色）→ 摘要卡 → 觀察卡 → 建議卡 →
進度卡 → 底部導覽列。沒有並排卡片（例如左右兩欄），維持
"一次只看一件事"的低資訊密度原則。

### Information Density（資訊密度）

每張卡片只放一個訊息重點（一句話+一張情境插畫），不會在
單一卡片塞入多筆數據或多段文字——這跟既有`design_tokens.js`
"低壓力"設計原則完全一致，不需要調整方向，只需要在未來的
呈現層轉換（Observation/Recommendation彙整成單句）時延續
這個密度控制。

### Spacing Rhythm（間距節奏）

卡片之間的垂直間距明顯大於卡片內部元素間距（例如標題跟底線
之間很緊湊，但這張卡片跟下一張卡片之間留白很多）——建議
既有`SPACING_TOKENS.layout.section`（28px）在Dashboard頁面
的實際卡片容器之間套用，`SPACING_TOKENS.card.gap`（14px）
套用在卡片內部元素之間，這個既有token設計已經支援這個節奏，
不需要調整數值。

### Mobile Layout Direction（行動裝置版面方向）

五張參考圖全部是iPhone風格的手機畫面（含狀態列/底部導覽），
確認Health Insight是**行動裝置優先**設計，既有`BREAKPOINT_
TOKENS`（mobile 0px→tablet 680px→desktop 1024px）的漸進式
放大方向正確，但**放大時不應該改變單欄卡片堆疊的核心體驗**
——桌面版本建議維持單欄、只是整體容器置中並限制最大寬度
（既有`getDesignSystemCSS()`已經在desktop斷點對`.hi-dashboard`
做了`max-width: 720px`置中處理，方向正確，不需要調整），而
不是在桌面版本改成多欄網格排版（那會破壞"一次只看一件事"的
節奏感）。
